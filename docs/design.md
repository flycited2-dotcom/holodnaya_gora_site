# «Холодная гора» — сайт: бриф и дизайн

## Цель
Один сайт, который одновременно:
1. **продаёт** — бронь домика и запись на стендовую стрельбу (рабочий инструмент, заявки приходят владельцу);
2. **развлекает** — браузерная мини-игра «стрельба по тарелкам»;
3. **информирует** — афиша мероприятий, «школа стенда», история места.

Приоритеты (со слов заказчика): стендовая стрельба — главное, отдых в домиках — второе.

## Что известно и что нет
| Известно (со слов заказчика) | Неизвестно — стоит как заглушка в `content/site.json` |
|---|---|
| База «Холодная гора», Белогорский район, Крым | точный адрес и координаты, телефон, e-mail, мессенджеры |
| Индивидуальные домики в лесу | количество/типы домиков, вместимость, цены |
| Стендовая стрельба по тарелкам — основная причина приезда | какие дисциплины и что входит в пакеты, цены, расписание |
| Мероприятия: Масленица, День охотника, конкурсы | реальные даты мероприятий |

Публично подтверждено (новости 2023, требует сверки с владельцем): охотничье хозяйство основано в 1956 г. по распоряжению Н. Хрущёва для разведения фазанов; плато на высоте около 500 м.

Всё неизвестное лежит в **одном файле** `content/site.json` с флагом `"draft": true`. Пока флаг включён, на сайте виден жёлтый баннер «черновик — данные-заглушки», чтобы заглушки не приняли за факты.

## Архитектура
Node.js 20+ без внешних зависимостей (один процесс, один JSON-файл данных) — деплой на любой VPS одной командой или в Docker.

```
server/   index.mjs (HTTP, статика, API) · booking.mjs (чистая логика: даты, пересечения, цена)
          store.mjs (JSON-хранилище, атомарная запись) · notify.mjs (Telegram) · limits.mjs (rate limit)
content/  site.json — контакты, домики, пакеты стрельбы, афиша, статьи
public/   index.html · css · js (scene, game, booking, events, main) · admin/
test/     node --test
```

Поток брони: форма → `POST /api/bookings` → валидация и проверка пересечений на сервере →
запись `pending` → уведомление в Telegram владельцу → владелец подтверждает/отклоняет в `/admin` → даты занимаются/освобождаются.
`pending` и `confirmed` блокируют даты; `cancelled` освобождает.

## API
- `GET  /api/content` — публичный контент (домики, афиша, пакеты, контакты)
- `GET  /api/availability?house=ID` — занятые даты домика
- `POST /api/bookings` — бронь домика
- `POST /api/requests` — запись на стрельбу / на мероприятие / вопрос
- `GET  /api/scores`, `POST /api/scores` — таблица лучших в игре
- `GET/PATCH /api/admin/*` — только с `Authorization: Bearer $ADMIN_TOKEN`

## Дизайн
Тёмный «лесной» интерфейс + сигнальный оранжевый цвета тарелочки. Заголовки — Unbounded, текст — Manrope (кириллица, шрифты лежат локально).
Иллюстрация — процедурная SVG/canvas-сцена (горы, туман, сосны), без стоковых фото: нельзя показывать выдуманные фото реальной базы. Слоты под настоящие фото — в `site.json`.

## Игра «Тарелочки»
Раунд = 25 тарелок (как официальный раунд трапа/скита). Мышь/тач/клавиатура, очки за дальность и серии,
звание по результату, таблица лучших на сервере. Пауза, выключатель звука, `prefers-reduced-motion`.

## 3D-домики
Three.js r170 лежит в `public/vendor/three/` (CSP запрещает чужие CDN), грузится лениво у раздела «Домики».
Процедурный домик (`js/tour3d/cabin.js`) и GLB-модель (`js/tour3d/model.js`) отдают один интерфейс
`{ group, anchors, smokeAt, fireAt, focus, clear, setSeason, setWarm, update, dispose }` — поэтому замена
иллюстрации на скан или купленную модель — это строка `model3d` в `site.json`, без правки кода.
Сезон в режиме «Авто» — по дате заезда из календаря брони (событие `hg:booking` из `booking.js`).
Нарисованный домик всегда подписан «3D-иллюстрация» — как и с фото, нельзя выдавать выдуманное за настоящую базу.

## Вне объёма первой версии (YAGNI)
Онлайн-оплата, личный кабинет, многоязычность, CMS. Оплата добавляется отдельным этапом, когда будет юрлицо/эквайринг.
