# Холодная гора — сайт базы отдыха

Интерактивный лендинг с бронированием: **стендовая стрельба** (главное), домики в лесу, игра «Тарелочки», афиша мероприятий, «школа стенда».
Node.js без внешних зависимостей, данные — в одном JSON-файле.

## Что умеет сайт

| Раздел | Что внутри |
|---|---|
| Стрельба | Пакеты с ценами, кнопка «Записаться» → заявка администратору |
| Тир онлайн | Игра: раунд из 25 тарелок (мышь, касание, клавиатура), звук, звания, таблица лидеров за месяц и за всё время |
| Школа стенда | Что такое стенд, трап / скит / спортинг со схемами, безопасность, «первый визит», факты |
| Домики | Карточки, календарь с занятыми датами, расчёт цены, заявка на бронь |
| Афиша | Мероприятия с фильтрами, запись, выгрузка в календарь (.ics) |
| О месте, контакты | История, телефон, карта |
| `/admin` | Брони и заявки: подтвердить / отменить, закрыть даты вручную, модерация рекордов |

Заявки приходят владельцу в **Telegram** (если настроен бот) и всегда сохраняются в админке.

## Быстрый старт

Нужен Node.js 20+.

```bash
cp .env.example .env     # впишите ADMIN_TOKEN (и при желании Telegram)
npm start                # http://localhost:3000
npm test                 # 29 автотестов
```

Админка: `http://localhost:3000/admin`, токен — значение `ADMIN_TOKEN`.

## Как заменить заглушки реальными данными

**Все тексты и цифры базы лежат в одном файле — [`content/site.json`](content/site.json).** Сервер перечитывает его без перезапуска, а при опечатке пишет в лог, что именно не так, и продолжает работать на прошлой версии.

Пока `"draft": true`, на всех страницах висит жёлтая плашка «Черновик — данные-заглушки». Заполните реальные данные и поставьте `"draft": false`.

### Что нужно узнать у владельца

- [ ] Телефон, e-mail, Telegram/WhatsApp, точный адрес и координаты ворот
- [ ] Часы работы стенда
- [ ] Домики: сколько, как называются, вместимость, цена за ночь, что внутри, **фотографии**
- [ ] Время заезда и выезда, минимальный срок проживания
- [ ] Стрельба: какие дисциплины реально есть (трап / скит / спортинг), пакеты, цены, что входит, возрастные ограничения
- [ ] Афиша: реальные даты мероприятий (в файле примеры: Масленица 14.03.2027, День охотника и др.)
- [ ] Историческая справка в разделе «О месте» (основание в 1956 г. как охотхозяйство для разведения фазанов — из открытых источников, **нужно подтверждение**)
- [ ] Юридические реквизиты оператора для `public/privacy.html` (политика — шаблон, покажите юристу)
- [ ] Нужна ли предоплата / онлайн-оплата (сейчас нет — бронь подтверждает администратор)

Фото положите в `public/img/` и впишите пути в `houses[].photos` (например `"/img/les-1.jpg"`) — карточка покажет фото вместо иллюстрации.

## 3D-домики

В разделе «Домики» под карточками есть блок «Осмотрите домик в 3D»: домик можно крутить мышью или пальцем, переключать день, закат и ночь (вечером загораются окна, фонарь и мангал, из трубы идёт дым), выбирать сезон. В режиме «Авто» сезон берётся из даты заезда в календаре брони: выбрали январь — домик в снегу. Оранжевые точки на домике — подсказки, по клику камера подлетает к месту.

Тем же 3D-движком рисуются картинки в карточках домиков (если у домика нет фото — настоящие фото всегда важнее).

**Сейчас домики нарисованы кодом** по данным из `site.json`: площадь задаёт размер, удобства — детали (терраса, мангал, печная труба с дровником). Домики до 26 м² — каркасные A-frame, остальные — срубы. На сцене подпись «3D-иллюстрация, не точная копия домика», чтобы гостей не ввести в заблуждение.

Three.js (`public/vendor/three/`, MIT) и сцена грузятся только когда гость подлистал к домикам — около 220 КБ в сжатом виде. На слабых телефонах меньше деревьев и частиц. Без WebGL блок не показывается, бронь работает как раньше.

### Как заменить иллюстрацию настоящим домиком

1. Получите модель в формате **GLB**:
   - **скан настоящего домика** — приложения Polycam, Luma AI или Scaniverse: обойти домик с телефоном 5–10 минут, затем экспорт «Mesh → GLB» (именно полигональная модель, не Gaussian splat);
   - **готовая модель** — купить на Sketchfab / CGTrader или заказать у 3D-моделлера, экспорт из Blender в GLB.

   Держите файл до 10–15 МБ: текстуры 2K, без Draco-сжатия (его этот сайт пока не распаковывает).
2. Положите файл в `public/models/`, например `public/models/les.glb`.
3. Добавьте домику в `content/site.json` поле `model3d`:

```json
"model3d": {
  "src": "/models/les.glb",
  "kind": "scan",
  "rotationY": 180,
  "chimney": [1.6, 5.4, -0.8],
  "hotspots": [
    { "anchor": "terrace", "title": "Терраса", "text": "Вид на лес и закат" },
    { "position": [0, 1.5, 3.2], "title": "Вход", "text": "Ключ — у администратора" }
  ]
}
```

| Поле | Что значит |
|---|---|
| `src` | путь к файлу модели на сайте (`.glb` или `.gltf`) |
| `kind` | `scan` — подпись «3D-скан домика», `model` — «3D-модель домика» |
| `scale` | масштаб. Обычно не нужен: модель в сантиметрах или миллиметрах подгоняется сама |
| `rotationY` | повернуть модель, градусы — чтобы вход смотрел на зрителя |
| `offset` | сдвиг `[x, y, z]` в метрах, если модель стоит не по центру |
| `chimney`, `fire` | где дымит труба и где горит мангал, `[x, y, z]` в метрах |
| `glow` | имена материалов окон, которые светятся ночью. По умолчанию — всё, где в имени есть `glass`, `window`, «стекл», «окн» |
| `hotspots` | точки-подсказки: `title`, `text` и место — `anchor` (имя объекта-пустышки в модели, например созданной в Blender) или `position` `[x, y, z]` |

Координаты для подсказок проще всего снять на самом сайте: откройте `/?debug3d#tour` и дважды кликните по нужному месту модели — сайт покажет `[x, y, z]`. Если у домика нет `src`, но есть `hotspots` с `anchor` (`terrace`, `mangal`, `chimney`, `interior`, `kitchen`, `door`, `parking`), меняются только тексты подсказок нарисованного домика.

Если файл модели не найдётся или окажется битым, сайт покажет нарисованный домик, а в консоли браузера будет предупреждение. Опечатки в `model3d` сервер покажет в логе, как и остальные ошибки `site.json`.

## Настройки (`.env`)

| Переменная | Зачем |
|---|---|
| `ADMIN_TOKEN` | Пароль для `/admin`. Без него админка выключена |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Уведомления о заявках. Бот — у @BotFather |
| `SITE_URL` | Публичный адрес (canonical, sitemap, ссылки в уведомлениях) |
| `METRIKA_ID` | Счётчик Яндекс.Метрики. Цели: `booking_submit`, `request_submit`, `game_start`, `game_finish`, `game_score_saved`, `event_ics`, `hero_clay_hit`, `tour_ready`, `tour_hotspot`, `tour_time`, `tour_season` |
| `TRUST_PROXY=1` | Если сайт за nginx — брать IP клиента из `X-Forwarded-For` |
| `DATA_DIR` | Где хранить данные (по умолчанию `./data`) |

## Развёртывание

### Docker

```bash
docker build -t holodnaya-gora .
docker run -d --name holodnaya-gora --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -v hg-data:/data --env-file .env holodnaya-gora
```

### nginx перед приложением

```nginx
server {
    server_name holodnaya-gora.example;           # + listen 443 ssl и сертификат (certbot)
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $remote_addr;   # именно так — иначе IP можно подделать
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

В `.env` тогда: `TRUST_PROXY=1`, `SITE_URL=https://ваш-домен`.

### Резервные копии

Все брони, заявки и рекорды — один файл `data/store.json` (в Docker — том `/data`). Копируйте его по расписанию (cron + `cp`/`rsync`).

## Устройство

```
server/   index.mjs   HTTP-сервер, статика, API, админ-API, заголовки безопасности
          booking.mjs чистая логика: даты, пересечения броней, валидация, цена (покрыта тестами)
          content.mjs проверка site.json · store.mjs JSON-хранилище с атомарной записью
          notify.mjs  Telegram · limits.mjs ограничитель частоты запросов
content/  site.json   данные базы
public/   index.html, css/, js/ (hero, game, booking, events, requests …), admin/, privacy.html
          js/tour.js + js/tour3d/  3D-домики: сцена, домик, лес, эффекты, загрузка GLB
          vendor/three/  Three.js r170 (локально — CSP не пускает скрипты с чужих серверов)
test/     node --test: логика брони, API (включая гонку одновременных броней), проверка site.json
docs/     design.md   бриф и дизайн-решения
```

Как защищена бронь: проверка пересечений и запись выполняются на сервере строго по очереди, поэтому два гостя не займут одни даты (тест: 5 одновременных заявок → создаётся одна). `pending` и `confirmed` занимают даты, `cancelled` освобождает; день выезда одного гостя доступен для заезда другого.

Безопасность: CSP без inline-скриптов, проверка Origin у POST (защита от CSRF), лимиты запросов, скрытое поле-ловушка для ботов, пользовательский текст везде выводится как текст (не HTML), сравнение токена за постоянное время, защита от выхода за пределы каталога.

## Известные ограничения

- Хранилище — один JSON-файл и один процесс. Для базы отдыха хватает с запасом; при росте нагрузки заменяется на SQLite/PostgreSQL в `store.mjs`.
- Таблица лидеров не защищена от накрутки со стороны браузера — это игра для удовольствия (сервер лишь отсекает невозможные результаты и ограничивает частоту отправки). Приз за рекорд лучше не привязывать к этой таблице без доп. проверки.
- Онлайн-оплаты нет: бронь — заявка, которую подтверждает администратор.
- Фото базы нет, вместо них нарисованная сцена и 3D-иллюстрации домиков — подставьте настоящие фото и, когда будет, скан домиков (см. «3D-домики»).
- В 3D пока нельзя зайти внутрь нарисованного домика — интерьер появится вместе со сканом или моделью.
